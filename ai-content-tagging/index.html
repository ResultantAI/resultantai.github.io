How it works

Five steps from inconsistent tags
to a self-maintaining content library

01

Taxonomy Audit & Schema Design

Existing tags are reviewed and classification dimensions defined — what the AI tags for, allowed values per dimension, and decision rules for edge cases. If no taxonomy exists, it is designed here before any classification starts.

02

Classification Prompt Engineering

Claude prompts built per taxonomy dimension, tested against a 50-item sample. Tuned until accuracy exceeds 95% on the test set. Confidence scoring calibrated — items below the threshold go to the review queue instead of being mislabeled silently.

03

Bulk Classification Run

Full library processed in batches. Output staged as a spreadsheet for your review before any tags are written to production. Your editorial team can approve by content type or dimension before anything changes in the CMS.

04

CMS Integration & Write-Back

Approved tags written to your CMS taxonomy fields via API. Field mapping documented. Auto-tag webhook configured — new content classified and tagged in seconds on publish, with no manual action required.

05

Review Queue & Handoff

Low-confidence items surfaced for editorial review. Taxonomy documentation delivered: what each tag means, how to handle edge cases, how to add new taxonomy values, and how to retag a batch without rebuilding the system.
